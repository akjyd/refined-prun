# RP 界面约束（zh-cn 分支）

最后更新：2026-11-06。依据：《Practical UI》(Adham Dannaway, 2nd ed., 2024)，括号内为原书页码；以及玩家（本分支用户）明确提出的要求，标注「用户」。

做任何新界面或改界面之前，逐条对照。

设计系统「RP 中文分叉」（claude.ai 上的 Design System 文档，含变量、组件说明和预览）是这些规则的图示版。代码里的变量在 `src/refined-prun.css` 的 `--rpz-*`，与它的 tokens.json 一一对应；改一个值，两边一起改。新窗口的颜色、间距、字号只能用 `--rpz-*` 变量，不写死数值。先出效果图，用户确认后再写代码（用户）。

## 1. 控件选型

1. 选项 ≤10 个：用单选标签 `src/components/ChipGroup.vue`（仿游戏 RadioItem 的样式；游戏原生 RadioItem 横排时指示条会压住文字，不用），不用下拉框。理由：下拉要多次点击、选项不可见、难比较（p.353）。用户明确拒绝下拉框。
2. 选项 >10 个且用户知道要找什么：用带建议的输入框（p.354）。
3. 依赖前一个选择才有意义的控件，前一个选择需要时才出现（渐进式披露，p.61）。例：路线「全部 / 自定义」，选「自定义」才出现起点、终点。
4. 不使用浏览器默认样式的白色输入框、白色下拉框（用户）。输入框：深色底（raised 层）、Stroke strong 边框、聚焦时橙色描边。
5. 数字小幅调整用步进器，不用下拉（p.356）。

## 2. 交互状态（p.47, p.109, p.142）

1. 每个可点击元素都有 hover 反馈：叠一层半透明白（约 6%）；按下叠约 10%。整行可点时整行 hover、`cursor: pointer`。
2. 选中状态不只靠颜色：单选标签用指示条 + 橙色，表格排序列显示箭头（p.85）。
3. 只能看不能点的东西，不要做得像按钮（p.171-173）。

## 3. 颜色

1. 橙色 `#f7a600` 只用于可交互元素、选中状态，以及「新出现 / 有变化」的标记（`--rpz-mark`；用户 2026-11-06：喜欢订单变化标记的金色）。可点击的文字平时用文字色，悬停才变金色，不用游戏的蓝色链接色（用户）。
2. 绿/红表示盈/亏（游戏惯例）；警告（风险高、数量超过成交量）一律用红色 `#d0524c`，不用品牌橙（用户 2026-11-05）。红色不能发粉（用户 2026-11-06）。成交、新机会不是警告，用金色标记。不用大面积红色装饰（用户：「红艳艳的太丑」）。
3. 破坏性操作（删除、加入黑名单）初始状态不染红，用第三级样式（p.322）。
4. 深色三层：base / raised / overlay 靠背景明度区分，不靠阴影（p.122）。背景带一点暖色。
5. 文字不用纯白（原书「避免纯黑和纯白」一节；用户 2026-11-06：「更喜欢水墨屏的那种感觉」）。四档墨色，按重要程度分配，不是整张表一个深浅（原书「视觉层级」一节：用颜色和对比度区分重要程度；用户）：
   - 墨 1 `--rpz-text-strong` #d8d6d0：每行做决定所依据的那一个数（ARB 的利润/天、ARBLOG 的实际利润），加粗；自己的订单；选中的标签。
   - 墨 2 `--rpz-text` #b3b1ab：普通内容（路线、价格、数量）。
   - 墨 3 `--rpz-text-weak` #85837e：次要数字（成本、成交量分母、安全倍数、天数、订单簿里别人的数量和公司名）、列头、标签。
   - 墨 4 `--rpz-text-off` #5c5b57：只用于不需要读的东西（分隔、停用）。不用于数字。
   在 #1f1f1e 上的 WCAG 对比度：墨 1 11.4，墨 2 7.7，墨 3 4.4，墨 4 2.4。
6. 盈亏颜色沿用游戏的 ColoredValue，和游戏窗口一致。

## 4. 信息

1. 每一列、每一个数字都要回答一个决策问题；答不出就删（p.56）。
2. 能画出来的关系就画出来，不堆数字列（用户：「标记出我要买到哪一个单子……画出来，而不是数据」）。
3. 界面里不写说明性句子、提示语（用户：「不要口水话」「正式一点」）。
4. 数字右对齐，等宽数字（`tabular-nums`）。

## 5. 操作位置（p.213）

1. 作用于某一行的操作放在该行的展开区里；作用于整个列表的操作放在工具栏。
2. 同一个功能只有一个入口（用户：「黑名单单独给一个按钮，不要每个东西都有」）。
3. 重复出现的操作用第三级按钮，不和主操作抢（p.306）。

## 5.5 表格

1. 所有数据表格用斑马纹：数据行加全局类 `rpz-row`，偶数行底色 `--rpz-zebra` = 2% 白，和 RP 给游戏表格加的斑马纹相同（`table-rows-alternating-colors.module.css`；用户 2026-11-06：3.5% 不如游戏里的好）。
2. 悬停必须和斑马纹分得开（用户）：`rpz-row` 悬停时底色 6%，左边加 2px 墨 3 竖线（`--rpz-hover-mark`）。全局规则零优先级，选中、订单状态的底色优先。
3. 变化标记（「新」「−50」）放在单独一列：固定宽度、右对齐、行内用基线对齐（`align-items: baseline`），和数字上下对齐，不压在图标上，不挤着数字（用户 2026-11-06：「怎么老是飘着」）。整行加 `rpz-marked` 淡金底。

## 6. 间距

游戏界面密度高，用 4px 网格：元素内 4，组内 8，组与组之间 16。关系越远间距越大（p.194）。

## 7. 一致性（用户反复强调）

同一个概念在 CXOB、XIT CX4、XIT ORDERS、XIT ARB 中外观和行为一致：
- 自己的订单显示「剩余/初始」，可拖拽改价，有改价按钮。
- 物资图标点击打开 MAT（除非点击另有用途）；星球名点击打开 PLI。
- 游戏里能点的东西，在中文窗口里也要能点，行为相同（用户 2026-11-06）。例：公司名点击打开 CO。例外：会改变游戏状态的操作（例如收藏）不照搬。
- 日利颜色规则相同（profitMarks）。
