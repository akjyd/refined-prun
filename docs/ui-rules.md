# RP 界面约束（zh-cn 分支）

最后更新：2026-11-05。依据：《Practical UI》(Adham Dannaway, 2nd ed., 2024)，括号内为原书页码；以及玩家（本分支用户）明确提出的要求，标注「用户」。

做任何新界面或改界面之前，逐条对照。

设计系统「RP 中文分叉」（claude.ai 上的 Design System 文档，含变量、组件说明和预览）是这些规则的图示版。代码里的变量在 `src/refined-prun.css` 的 `--rpz-*`，与它的 tokens.json 一一对应；改一个值，两边一起改。新窗口的颜色、间距、字号只能用 `--rpz-*` 变量，不写死数值。先出效果图，用户确认后再写代码（用户）。

## 1. 控件选型

1. 选项 ≤10 个：用单选标签 `src/components/ChipGroup.vue`（仿游戏 RadioItem 的样式；游戏原生 RadioItem 横排时指示条会压住文字，不用），不用下拉框。理由：下拉要多次点击、选项不可见、难比较（p.353）。用户明确拒绝下拉框。
2. 选项 >10 个且用户知道要找什么：用带建议的输入框（p.354）。
3. 依赖前一个选择才有意义的控件，前一个选择需要时才出现（渐进式披露，p.61）。例：路线「全部 / 自定义」，选「自定义」才出现起点、终点。
4. 不使用浏览器默认样式的白色输入框、白色下拉框（用户）。输入框：深色底（raised 层）、Stroke strong 边框、聚焦时橙色描边。
5. 数字小幅调整用步进器，不用下拉（p.356）。

## 2. 交互状态（p.47, p.109, p.142）

1. 每个可点击元素都有 hover 反馈：叠一层半透明白（约 6%）；按下叠约 10%。整行可点时整行 hover、`cursor: pointer`。
2. 选中状态不只靠颜色：单选标签用指示条 + 橙色，表格排序列显示箭头（p.85）。
3. 只能看不能点的东西，不要做得像按钮（p.171-173）。

## 3. 颜色

1. 橙色 `#f7a600` 只用于可交互元素和选中状态（p.96）。
2. 绿/红表示盈/亏（游戏惯例）；警告（风险高、数量超过成交量）一律用红色，不用品牌橙（用户 2026-11-05）。不用大面积红色装饰（用户：「红艳艳的太丑」）。
3. 破坏性操作（删除、加入黑名单）初始状态不染红，用第三级样式（p.322）。
4. 深色三层：base / raised / overlay 靠背景明度区分，不靠阴影（p.122）。文字：strong `#eee`，weak `#8c8c8c`。对比度用 APCA 实测，不自行估算 Lc 值。

## 4. 信息

1. 每一列、每一个数字都要回答一个决策问题；答不出就删（p.56）。
2. 能画出来的关系就画出来，不堆数字列（用户：「标记出我要买到哪一个单子……画出来，而不是数据」）。
3. 界面里不写说明性句子、提示语（用户：「不要口水话」「正式一点」）。
4. 数字右对齐，等宽数字（`tabular-nums`）。

## 5. 操作位置（p.213）

1. 作用于某一行的操作放在该行的展开区里；作用于整个列表的操作放在工具栏。
2. 同一个功能只有一个入口（用户：「黑名单单独给一个按钮，不要每个东西都有」）。
3. 重复出现的操作用第三级按钮，不和主操作抢（p.306）。

## 6. 间距

游戏界面密度高，用 4px 网格：元素内 4，组内 8，组与组之间 16。关系越远间距越大（p.194）。

## 7. 一致性（用户反复强调）

同一个概念在 CXOB、XIT CX4、XIT ORDERS、XIT ARB 中外观和行为一致：
- 自己的订单显示「剩余/初始」，可拖拽改价，有改价按钮。
- 物资图标点击打开 MAT（除非点击另有用途）；星球名点击打开 PLI。
- 日利颜色规则相同（profitMarks）。
